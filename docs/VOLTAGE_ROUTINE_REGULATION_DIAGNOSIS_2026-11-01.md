# Voltage标签与常规调压的对应核查

## 核查问题与保持不变的条件

本次只读核查回答：V4中近乎恒正的Voltage，是否代表常规调压之后仍存在的电压风险。全部896条分支、28个日期、5376条分支小时记录已完成采集；独立保存记录核验共509440项检查，错误为0。原始拓扑、阻抗、机组P/Q边界、0.9 kA线路额定值、0.93–1.07 pu电压范围、充电站容量、运行标签、旧RL与旧专家均未修改。下面的静态AC探针独立保存在diagnostics目录，不进入训练集，不替换既有标签，不重放交通或采集新分支。

## 当前代码实际判定的对象

`environment.step`先取得完整MPC例行计划，再以真实小时负荷与真实充电交付，在`network.pressure`中固定本地机组P/Q、可再生能源使用指令、备用与基础负荷比例，计算一组不执行的AC潮流。根节点维持1 pu，平衡损耗及预测偏差。Voltage标签是该诊断点是否越过0.93–1.07 pu，并采用1e-6 pu数值容差；不是电压偏差或节点间压差。随后`network.dispatch`重新优化P/Q、弃发及必要的保护处理，只有经独立AC核验的运行点才被提交。

因此当前标签严格对应“完整MPC指令固定时的纠正前AC越限”，没有区分常规无功调压与超出常规能力的额外处置。`correction_evidence`记录Q发生变化，并不能证明这种变化属于应急措施；全约束OPF同时优化多个控制量，也不能证明其有功调整或弃发专门由电压越限强迫产生。

这里的“纠正前越限”确实来自AC方程，不是把0.98 pu之类正常质量变化误读成故障。但这些潮流点没有被实际执行，不能据此声称真实运行系统有99.78%的窗口发生电压故障。“六小时内任一小时越限”的OR汇总进一步使窗口标签饱和，而实际运行保持合规。

## 根因之一：近似MPC合规并不等于AC计划合规

对4592条MPC自身给出的计划小时（所有接续小时及参考行动首小时），用计划当时可见的预测和相同指令重建线性电压，越限数为0；其中2724条（59.32%）距离边界不足1e-5 pu。对同一预测与指令计算AC潮流，线性最低电压与AC最低电压之差的中位数为0.00967 pu，95%分位为0.03795 pu，最大0.05054 pu。这一差异在没有使用未来扰动的情况下已经存在。

线性MPC的电压近似忽略了完整AC非线性与损耗效应；在成本最优且贴边的计划上，该误差会直接转为纠正前低电压。无功的字典序最小绝对值只消除了无代价的大幅环流，没有保证更准确的AC可行性。所有计划小时的本地机组最大无功占额定比例中位数为11.28%，最大28.78%，也不支持“原生无功资源普遍耗尽”的解释。

这些结果定位的是规划—执行模型的一致性问题，而不是电压阈值过严或线路容量不足。原参数无需为消除该现象而放宽。

无功二级目标还有明确的结构性不足。在当前无损模型中，每个馈线有`sum(Qg)=sum(Qload)`；只要各机组均为非负供无功，`sum(abs(Qg))`就等于固定的总无功负荷。这个目标能消除正负无功环流，却不能在许多同优解之间识别更合理的空间分配。因此LP仍可能选择贴着0.93 pu的顶点。该结论来自模型约束与目标的代数关系，不能通过单纯增加预警器容量解决。

## 隔离对照：固定有功与交付，仅改变无功控制

静态探针预先按物理条件选取：每个日期、每个分支时点的profile0参考行动第1/3/6个未来小时，再加入该日期纠正前越限最严重的一条去重记录。合计196条，覆盖全部28个日期。选择不使用任何预测器的正确率、分数或排序。

第一种探针将已经保存的安全执行点的本地Q代入纠正前计划，其他本地P、RE指令、备用、基础负荷比例与实际EV交付保持不变。它检验“现有记录是否已经给出无需改变这些有功安排的Q可行解”，不寻求最优Q。

第二种探针在同样固定有功的条件下，让8台本地机组采用1 pu电压设定的PV控制，并严格执行原生Q上下限；达到Q限额时转为PQ求解。根节点继续平衡AC损耗。没有增加调压设备或无功能力。该对照是常规有界电压调节的可行性检验，不冒充原V2SIM所有机组的原生控制模式，也不预先写入当前环境。

PV与固定PQ模式的区别及Q限额处理可参照[pandapower generator文档](https://pandapower.readthedocs.io/en/v3.1.1/elements/gen.html)与[MATPOWER AC power flow说明](https://matpower.app/manual/matpower/ACPowerFlow.html)。有界调压必须核对实际Q，而不能只设PV后忽略限额。

两种简单Q控制不能直接替代情境化调压。在146个原先越限点中，复制已执行点的Q消除了25个，却使10个原先不越限点产生新越限；统一1 pu有界PV消除了91个，却使2个原先不越限点越限。这说明Q需要结合保持不变的有功及注入分布重新协调，不能直接迁移另一套运行点的Q，或假设统一电压设定对所有位置都足够。

第三种探针进一步固定所有非平衡节点有功、RE逐源逐节点利用、备用、基础负荷比例与EV真实交付，只在原生Q范围内做全约束AC可行性求解。根节点仍按原生P/Q边界平衡损耗；未放开禁止反送约束，未加设备、放大容量或改变电压范围。求解后将所有非平衡节点有功钳回精确原指令，再独立计算潮流，核对P/Q、线路、电压及节点平衡。

|---|---:|
| 选定诊断点/日期 | 196/28 |
| 其中原先Voltage越限点 | 146 |
| 固定全部上述有功安排，仅调Q找到完整物理可行点 | 135/146（92.47%） |
| 其中原先除Voltage外没有出口许可越界 | 134 |
| 原先越限但Q-only求解未得到核验点 | 11 |

| 已核验正例解中最大机组无功占原生额定比例 | 32.39% |

135个可行点是存在性证据：在这些诊断点中，不需要相对原计划新增限充、弃发、备用或基础负荷削减，就可以满足当前完整物理边界。其中134个点可单独作为纯Voltage的常规调压可行性证据，另1个同时涉及原有出口许可越界，不用它论证“仅有电压问题”或“调压代价为零”。调Q还会改变AC损耗及平衡节点供电，不能把“不调整本地有功”写成“不发生任何能量或成本变化”。

未核验的11个越限点全部属于数值未知，不是证明常规Q不可行，更不是已经证明必须弃发或削负荷。统一1 pu策略也不是Q-only最优方案。这里的研究结论是常规调压需求被大量混入当前风险标签，不是声称已经找到一个适用于所有状态的完美控制器。

这是代表性时点与极端点构成的诊断样本，92.47%不外推为全部5376小时的比例。静态探针以当前小时实际交付为已知边界条件，证明该小时的准稳态可行性，不替代一套完整的有限信息调压闭环。

## 当前运行与证据使用

V4原协议继续执行，保留它作为冻结P/Q计划诊断的完整基线。物理核验已完成；启动器曾因Windows PowerShell未保留子进程句柄、读到空ExitCode而误报失败，已用真实退出0/7的两个用例复现并修复。原失败状态和日志保留，896条采集不重复，初始预警器训练已完成并进入128次信息采样。

当前结果不应将Voltage高频正例或其参与的复合召回直接解释为“难以避免的真实复合风险”。更有解释力的后续定义是：先纳入指定的常规调压能力，再区分剩余电压越限、需要的额外有功/弃发/服务代价及最终后果。是否采用这一新定义属于下一隔离版本；本轮未改动标签。

结论是：标签代码没有把合规电压偏差误算为越限，但其反事实基准冻结了Q，把常规调压与额外应急纠正混为一类；MPC近似贴边又放大了这种现象。需要修正的是控制基准与风险任务的对应关系，不能靠放宽电压阈值、缩小线路或扩大模型来处理。未来若升级，常规有界Q控制和AC计划核验应属于正常运行机制，Voltage风险则评估其后仍未消解的边界压力或明确额外处置后果。应先复用已封存状态诊断新标签支持度，再决定是否需要重新采集；不能把当前V4标签静默覆盖成新结果。
